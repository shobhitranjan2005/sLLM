Architecture

  • Tokenizer: SentencePiece Unigram, vocab_size=8192, byte-fallback, normalization_rule_name="identity", add_dummy_prefix=False. The last two are non-default settings needed specifically because default SentencePiece normalization and prefix-space insertion silently break exact decode(encode(text)) == text round-trip on Devanagari text — verified lossless before training (round_trip_ok=True).
  • Position encoding: RoPE (rotary), replacing learned absolute position embeddings — frees the block_size × n_embd parameter table and encodes relative position, which needs fewer gradient steps to become useful than a learned table trained from scratch.
  • Normalization: RMSNorm, replacing LayerNorm — drops mean-centering and the bias term.
  • MLP: SwiGLU (gate/up/down, hidden dim ≈ 2/3 of the standard 4× GELU-MLP hidden size to hold parameter count roughly constant).
  • Init: GPT-2-style scaled residual init — each block's residual-stream output projection (attention proj, MLP down-projection) initialized with std scaled by 1/√(2·n_layer), keeping residual-stream variance from compounding with depth.
  • Weight tying: token embedding and output head share weights.
  • Optimizer (final): plain Adam (lr=3e-3, betas=(0.9, 0.95)), linear warmup over 100 steps, cosine decay to 10% of peak LR, global gradient-norm clipping at 1.0.
  • Config: n_layer=4, n_head=4, n_embd=128, block_size=256, dropout=0.0. Total: 1,827,968 params (cap: 2,000,000).

What we tried and rejected

Muon optimizer (Newton-Schulz orthogonalized updates) for the 2D transformer-block matrices, AdamW for embeddings/norms — motivated by the nanoGPT-speedrun result that orthogonalized updates converge faster per-step within small, fixed step budgets. Ablated head-to-head against plain Adam with the architecture held fixed: Muon+AdamW scored 1.7210 bpb, plain Adam scored 1.7067 bpb — Muon lost by 0.83% relative, consistently across the entire training curve, at roughly equal wall-clock time. Most likely explanation: the ablation reused the AdamW-tuned learning rate for the all-Adam run instead of independently tuning each optimizer, and Muon's typical advantage is better established at larger batch sizes than the batch size of 8 used here. We shipped the simpler, better-scoring plain-Adam configuration rather than chasing a fix for Muon, given the cost of further full 2,000-step runs (~11 min each) against the marginal potential upside.
